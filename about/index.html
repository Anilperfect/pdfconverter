About FileForge

FileForge is a file conversion website built around one idea: keep the user's file on the user's device whenever that is technically possible.

Three processing modes

Every tool in the registry declares where its work happens. The registry lives in src/lib/tools.ts and drives the navigation, the tool hub, the sitemap and each tool page.

1. Browser mode (44 tools)

The file is read with the browser File API and converted in the tab using jsPDF, PDF.js, pdf-lib, JSZip and the canvas API. Nothing is uploaded, so these tools keep working offline once the page has loaded and they scale with the user's own hardware.

2. API mode (7 tools)

Image encoding is one place where a server genuinely helps: Sharp produces smaller, better encoded files than the canvas API. The upload goes to a Next.js route handler, is validated from its real file signature, processed in memory and streamed straight back. No temporary file is ever written.

3. Worker mode (23 tools)

Office, OCR, audio, video and very large documents need engines that cannot run in a page. Those tools are registered but deliberately not wired up: the interface shows “Worker required” instead of returning a file that was never converted.

Security posture

  • The browser's Content-Type header is never trusted; uploads are checked by file signature.
  • Output filenames are rebuilt server-side from an allowlist of characters.
  • File size, pixel count and archive expansion limits are enforced before decoding.
  • Rate limiting is applied per IP on the API route.
  • Strict security headers, including a restrictive Content-Security-Policy, are set on every response.
  • Error messages shown to users are generic; internal details stay in the server logs.

What is intentionally missing

There is no user account, no database, no analytics and no third-party script. Nothing about your files is stored, and the site sets no cookies of its own — only a theme preference in localStorage.

Current status

51 of 74 registered tools are live. The remaining 23 need the background worker described in the FAQ and the project README.

Note on placeholders. The site URL and contact address in this build are placeholders. Replace SITE.url and SITE.contactEmail in src/lib/seo.ts (plus the matching environment variables) before publishing.
